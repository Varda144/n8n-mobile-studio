# N8N Mobile Studio

A native Kotlin/Jetpack Compose Android app that runs real software **on the
phone**: an embedded Node.js engine, an n8n instance served from the app's own
storage, and a terminal + GUI that both drive those same local processes. No
Termux, no remote server, no second toolchain.

The project is developed from a phone: Android builds run in GitHub Actions rather
than requiring Android Studio on the development device.

## What is actually embedded

This section is the contract. Nothing here is claimed until the artifact exists
in the APK and starts on a device — `assets/runtime/manifest.json` is generated by
the payload build, and `scripts/verify-runtime.sh` fails the build if a claim is
not backed by a real file with a matching digest.

| Piece | How it is packaged | State in this repository |
| --- | --- | --- |
| Node.js engine | `jniLibs/<abi>/libnode.so`, cross-compiled from the pinned Node release with upstream's `android-configure` (plus the NDK `libc++_shared.so` next to it) | build script + manifest fields ready; built by the payload build, not committed (tens of MB) |
| n8n | npm production tree (+ `better-sqlite3` cross-compiled against the engine headers) zipped into `assets/runtime/n8n/payload.zip`, launched as `libnode.so n8n/bin/n8n start` | build script + installer + supervisor ready; payload produced by the payload build |
| OpenCode | would be `assets/runtime/opencode/payload.zip`, launched as `libnode.so opencode/server.js serve …` | **NOT_PACKAGED**: upstream ships Bun single-file binaries (linux/darwin/windows, glibc/musl) and the server targets Bun APIs. The app reports `NOT_PACKAGED` and never substitutes a remote service or a stub server |

The app shows exactly this state in **LOCAL → n8n / OPENCODE**, and Settings shows
the device/engine report (`node --version` probe, ABI, storage). A runtime only
reaches `RUNNING` after its payload launches *and* answers its loopback health
probe; otherwise it reports `NOT_INSTALLED`, `FAILED` or `DEGRADED` with the reason.

## Architecture

```
android/app/src/main/kotlin/com/n8n/mobile/studio/
  core/                constants, config, logging
  runtime/             pure-JVM engine: paths, payloads, installer, process,
                       supervisor, policy, health, manifest, logs, memory policy
  runtime/n8n/         n8n specifics: pinned version, env, storage, process, health
  runtime/opencode/    same shape for OpenCode
  runtime/android/     Android glue: app paths, native lib dir, payload sources
  runtime/service/     foreground service that owns both processes + binder client
  terminal/            the app's own command interpreter (no /bin/sh)
  domain/, data/, ui/  models, storage, screens (Compose)
```

* **One owner per process.** `LocalRuntimeService` (foreground, `dataSync`) owns
  every spawned process through `RuntimeSupervisor`; the GUI and the terminal call
  the same service methods, so they can never disagree about what is running.
* **Lifecycle is a state machine.** `RuntimePolicy` decides start/stop/restart,
  backoff (`1s → 60s`, give up after 5 attempts), health gating, idle stop
  (15 min), stop-then-kill grace, and low-memory eviction of the lower-priority
  runtime. It is pure JVM code and is unit tested.
* **Payloads are verified, never trusted.** Archives are digested while being
  streamed, entries are checked against zip-slip, installs are staged and renamed
  atomically, and the newest two versions are kept for rollback.
* **Loopback only.** n8n listens on `127.0.0.1:5678`, OpenCode on
  `127.0.0.1:8765`; cleartext traffic is permitted only for loopback addresses,
  and `RuntimeHealth` refuses to probe anything else.

## Building the payloads

```bash
# everything: Node engine for Android + n8n payload + manifest (+ OpenCode attempt)
scripts/prepare-runtime.sh

# individual pieces
scripts/build-node-android.sh arm64-v8a
scripts/build-n8n-payload.sh arm64-v8a
scripts/generate-runtime-manifest.py
scripts/verify-runtime.sh

# an APK with the payloads inside (assemble tasks, opt-in per branch)
printf 'my-branch\n' > runtime-payload.request
cd android && ./gradlew assembleDebug
```

Payload sources are build outputs and are git-ignored: they are tens of megabytes
of pinned third-party code. `runtime-payload.request` lists the branches whose APK
builds should build payloads; remove the line to keep ordinary builds fast.

## Verification without a local Android SDK

```bash
tools/compile-check/run.sh          # compile + run the unit tests on a plain JVM
tools/compile-check/run.sh --compile
```

This harness fetches a JDK (PyPI `jdk4py`) and the Kotlin compiler (npm
`kotlin-compiler`) into `/tmp`, then type-checks and runs everything that does not
need Compose, using hand-written stubs for the Android/coroutines/serialization
surface. It exists because this project cannot rely on Maven being reachable; it is
a development aid, not a replacement — Gradle in CI stays authoritative, and
failing CI runs republish compiler errors as annotations (`android/gradlew`
tees Gradle output and emits `::error::` lines).


## Security

n8n's encryption key and provider API keys live in the Android Keystore
(`security/`), never in source or CI logs. The runtime processes only see the
app's private files directory, and the terminal is a fixed command set over that
directory rather than a shell.
